# 中心化交易钱包系统组成

## 一 签名机

管理密钥，进行交易签名，安全级别要求很高。

### 最高级别

- CloudHSM：用来管理热钱包的私钥，硬签名机制，密钥在硬件
- Tee + S3: 交易所用户的钱包私钥管理在TEE里

### 最低级别

- 用户和热钱包私钥加密存储数据库

> 名词解释
>
> - CloadHSM:google或者AWS提供一种云上硬件密钥管理和签名服务
> - Tee:安全的可执行环境，常用AWSnitroenclave包裹程序，vsock通信方式，密钥加解密和签名都在Tee环境执行，由于AWSnitrotee没有存储，因而私钥加密之后会存到S3数据库。
> - 数据库:mysql, Postgres

## 二、钱包链路风控系统

伴随整个业务周期存在，从用户发起交易 → 签名 → 广播 → 上链 → 结算的全流程，每一步都做风险识别、拦截、延迟、复核，防止盗币、洗钱、诈骗、跑分、内部作恶的 “安全大脑”。

**目标**

- 防盗币：账号被盗、私钥泄露、设备劫持
- 防洗钱（AML）：黑钱、跑分、混币、资金拆分归集
- 防诈骗：钓鱼地址、恶意合约、授权盗币
- 防内部作恶：员工提权、私自转币、权限滥用

同时要：安全和体验平衡，小额快放、大额严审、异常延迟。

## 三、 钱包链路风控七层防护

### （1）接入层风控

这是最外层，可以阻挡脚本、爬虫、撞库。

检查：

- IP 异常（高风险国家 / 代理 / 机房 IP）
- 设备指纹（陌生设备、root / 越狱、多开）
- 频率限制（1 分钟请求次数、接口防刷）
- 登录态（token 被盗、异地登录）

动作：可以通过直接拦截+验证码 + 设备二次认证实现。

### （2）用户/账户风控

检查：

- KYC 等级（未实名 / 初级 / 高级，额度不同）
- 账户年龄（新号 < 24h、老号）
- 安全设置（刚改密码 / 邮箱 / 2FA，冷静期）
- 历史行为（常用金额、时间、地址、链）

动作：新用户限额、改安全设置延迟 24h、异常行为触发人脸 / 2FA。

### （3）交易行为风控

检查：

- 金额异常（单笔 / 单日限额、比平时高 5 倍）
- 地址异常（首次提现地址、黑名单地址、合约地址）
- 链异常（突然从 ETH 换到 高风险链）
- 路径异常（充值→秒提、小额频繁进出）
- 授权异常（无限授权、授权陌生合约）

动作：

- 小额：直接放行
- 中风险：延迟 + 人工审核
- 高风险：直接拦截 + 冻结。

### （4）链上地址风控

对接链上黑名单，可以通过慢雾、Chainalysis、Nansen
实时查：

- 地址是否黑产 / 诈骗 / 洗钱 / 暗网
- 是否与钓鱼合约、黑客地址交互
- 资金来源是否有赃款痕迹

命中黑名单直接拒绝交易并上报。

### （5）资产层风控

核心：冷热钱包 + 多签 + 限额，防大额被盗，热钱包少放钱、大额走冷钱包、多签审批+人工审批

- 热钱包：日常提现，额度≤5% 总资产
- 温钱包：中等金额，自动审批 + 多人复核
- 冷钱包：大额资产，私钥离线、多签（如 3/5、5/7）+ 时间锁（48h）

动作：超额自动切冷钱包、大额强制多签 + 人工审批。

### （6）签名与广播风控

核心：防签名泄漏，恶意广播

- 私钥永不触网（MPC/TEE/ 硬件钱包）
- 交易参数校验（nonce、gas、to、value）
- 广播节点风控（防止被劫持到恶意节点）

动作：异常参数拒绝签名、私钥全程离线。

### （7）链上确认风控

防假成功、双花、回滚

- 交易是否打包上链
- 是否被 RBF 替换、双花
- 是否被区块回滚

## 四、钱包服务层

- 扫链监控交易
- 构建交易发给签名机签名
- 发送交易到区块链网
  充值，提现，归集，转冷，冷转热等业务整理，归类，通知上层业务。
