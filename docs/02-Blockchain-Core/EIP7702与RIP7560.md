# 一、 EIP-7702

EIP-7702是以太坊创始人等提出的一项账户抽象（AA）提案，旨在提升外部账户的功能，使其在单笔交易中临时具备智能合约账户的能力，从而实现更灵活、更安全的用户体验。

## 核心机制

EIP-7702引入了一种新的交易类型，允许EOA在交易执行期间临时加载一段智能合约代码(称为contract_code)，该代码仅在该笔交易中有效，交易结束后自动移除，EOA恢复为原始状态。

```
rlp([chain_id, nonce, max_priority_fee_per_gas, max_fee_per_gas, gas_limit, destination, value, data, access_list, authorization_list, signature_y_parity, signature_r, signature_s])
```

其中，`authorization_list` 包含了授权信息，用于验证和加载临时的 `contract_code`。

## 优势亮点

EIP-7702引入了新的交易类型，使EOA能够在单笔交易中获得智能合约的能力，带来了以下优势：

- **兼容ERC-4337账户抽象**：EIP-7702与现有的账户抽象标准ERC-4337兼容，便于现有基础设施的迁移和集成。
- **增强安全性**：由于`contract_code`仅在交易期间有效，减少了长期部署代码带来的安全风险。
- **降低Gas费用**：合约代码临时加载，无需部署到链上，降低了用户成本，提升了交易效率。

## 潜在挑战

- **智能合约代码的安全审核**：临时加载的`contract_code`可能存在漏洞，需要在交易执行前进行充分的安全验证。
- **交易确认延迟**：由于需要在交易执行时验证代码，可能会增加交易的确认时间。

## 与其他提案的对比

| 特性         | EIP-7702       | EIP-4337      | ERC-4337      |
| ------------ | -------------- | ------------- | ------------- |
| 账户类型     | EOA + 临时合约 | 智能合约账户  | 智能合约账户  |
| 交易发起方式 | 原生交易       | UserOperation | UserOperation |
| Gas支付方式  | 原生支付       | 赞助/原生     | 赞助/原生     |
| 部署需求     | 无需部署       | 需要部署      | 需要部署      |

# 二、 RIP-7560

RIP-7560是一个以太坊改进提案，与EIP-7702形成互补关系。

## 核心要点

- **与EIP-7702的关系**：RIP-7560与EIP-7702是互补而非直接配套的关系，二者共同推动账户抽象的发展。
- **协议层集成**：专注于协议层的集成与去中心化设计。

## 动机

RIP-7560的核心动机是解决ERC-4337账户抽象方案存在的架构缺陷，旨在通过协议层的优化提升账户抽象的安全性和效率。

## 设计目标

RIP-7560的设计目标更聚焦于：

- **协议层集成**：实现账户抽象在协议层的原生支持，减少对中心化基础设施的依赖。
- **去中心化**：通过去中心化设计，提高账户抽象系统的抗审查能力和鲁棒性。
- **与EIP-7702互补**：与EIP-7702形成互补，共同推动以太坊账户抽象生态的发展。
