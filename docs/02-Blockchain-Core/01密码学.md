区块链密码学主要由两条支柱撑起：**哈希函数**（确保数据不可篡改）和**非对称加密**（确保所有权与授权）。

# 一、哈希函数

可以理解为数据的指纹，通过哈希函数将数据转换为固定长度的字符串，这个字符串就是数据的哈希值。
在区块链中，它用于生成区块哈希、交易哈希以及地址。Hash 算法也称为单向散列函数（杂凑函数），具有单向性，可以通过 X Hash 得到 H(X)，但是不能由 H(X) 反推出X。

- 抗碰撞性 (Collision Resistance)： 极难找到两个不同的输入得到相同的哈希值。
- 不可逆性： 无法从哈希值推导出原始数据。
- 雪崩效应： 原始数据哪怕改动一个比特，生成的哈希值也会天差地别。

**主流算法：**

目前常见的Hash算法包括MD5和SHA系列算法。MD5和SHA1已经被破解，一般推荐至少使用SHA2-256或更安全的算法。

- SHA-256： 比特币的核心，用于工作量证明 (PoW)。

- Keccak-256： 以太坊 (EVM) 使用的算法。注意： 它和标准的 SHA-3 略有不同，这在编写多链 SDK 时是常见的坑。

### 🔐 AES (Advanced Encryption Standard) - 高级加密标准

#### 📖 AES 简介

AES 是目前最广泛使用的对称加密算法，由美国国家标准与技术研究院（NIST）于2001年发布，取代了过时的DES算法。


| 特性       | 描述                |
| -------- | ----------------- |
| **类型**   | 对称加密（加密和解密使用相同密钥） |
| **密钥长度** | 128位、192位、256位    |
| **分组长度** | 128位（16字节）        |
| **安全性**  | 目前未被破解，被认为是安全的    |
| **性能**   | 硬件加速支持，速度快        |


---

#### 🎯 AES 工作原理

AES 基于替代-置换网络（SPN），通过多轮的替换和混淆操作来加密数据。

**加密流程：**

```
明文 → 密钥扩展 → 多轮变换 → 密文
```

**每轮变换包括：**

1. **字节替换（SubBytes）**：使用S盒进行非线性替换
2. **行移位（ShiftRows）**：对矩阵的行进行循环移位
3. **列混淆（MixColumns）**：对矩阵的列进行线性变换
4. **轮密钥加（AddRoundKey）**：与轮密钥进行异或操作

**轮数（根据密钥长度）：**

- AES-128：10轮
- AES-192：12轮
- AES-256：14轮

---

#### 🔧 AES 工作模式

AES 本身是分组加密，每次只能加密128位数据。对于长数据，需要使用工作模式。


| 模式      | 特点          | 适用场景    | 安全性           |
| ------- | ----------- | ------- | ------------- |
| **ECB** | 相同明文产生相同密文  | 简单加密    | ⚠️ 不安全，易被模式分析 |
| **CBC** | 使用初始化向量（IV） | 通用加密    | ✅ 安全，常用       |
| **CTR** | 将分组密码转为流密码  | 高性能场景   | ✅ 安全，可并行      |
| **GCM** | 提供认证加密      | 需要完整性验证 | ✅ 安全，推荐       |
| **XTS** | 专门用于磁盘加密    | 存储加密    | ✅ 安全          |


**推荐模式：**

- 一般用途：**CBC** 或 **CTR**
- 需要完整性验证：**GCM**（认证加密）
- 磁盘加密：**XTS**

---

#### 🌐 AES 在区块链中的应用

虽然区块链主要使用非对称加密（如ECC），但AES在以下场景中非常重要：


| 应用场景     | 用途             | 示例            |
| -------- | -------------- | ------------- |
| **钱包加密** | 用AES加密私钥，存储到本地 | MetaMask、硬件钱包 |
| **数据传输** | 加密节点间的通信数据     | P2P网络加密       |
| **智能合约** | 链下数据加密         | 可信执行环境（TEE）   |
| **隐私保护** | 加密敏感数据         | 零知识证明中的辅助加密   |

#### ⚠️ AES 使用注意事项

1. **密钥管理**
  - 密钥必须安全存储，不能硬编码
  - 使用密钥派生函数（如PBKDF2）从密码生成密钥
  - 定期更换密钥
2. **初始化向量（IV）**
  - IV必须是随机且唯一的
  - IV不需要保密，但必须随密文一起传输
  - 绝不能重复使用相同的IV和密钥组合
3. **认证加密**
  - 推荐使用GCM模式，提供机密性和完整性
  - 验证认证标签（Auth Tag）防止篡改
4. **填充攻击**
  - CBC模式易受填充预言机攻击
  - 使用GCM或CTR模式可避免

#### 🔍 AES 安全性分析


| 攻击类型       | AES-128        | AES-192        | AES-256         |
| ---------- | -------------- | -------------- | --------------- |
| **暴力破解**   | 2¹²⁸           | 2¹⁹²           | 2²⁵⁶            |
| **量子计算威胁** | Grover算法降低到2⁶⁴ | Grover算法降低到2⁹⁶ | Grover算法降低到2¹²⁸ |
| **实际安全性**  | 目前安全           | 目前安全           | 长期安全            |


**结论：**

- AES-128：对当前威胁足够安全
- AES-256：对量子计算威胁有更好抵抗
- 建议：一般用途用AES-256，性能敏感场景用AES-128

#### 📚 AES 实现示例

**Python 示例：**

```python
from Crypto.Cipher import AES

# 生成密钥和IV

iv = get_random_bytes(16)
```

**Go 示例：**

```go
import (
    "crypto/aes"
    "crypto/cipher"
    "crypto/rand"
)

func encrypt(key, plaintext []byte) ([]byte, error) {
    block, err := aes.NewCipher(key)
    if err != nil {
        return nil, err
    }

    gcm, err := cipher.NewGCM(block)
    if err != nil {
        return nil, err
    }

    nonce := make([]byte, gcm.NonceSize())
    if _, err = rand.Read(nonce); err != nil {
        return nil, err
    }

    return gcm.Seal(nonce, nonce, plaintext, nil), nil
}
```

## 2.2 非对称加密

非对称加密使用一对密钥：加密密钥和解密密钥是不同的，分别称为**私钥 (Private Key)** 和 **公钥 (Public Key)**。私钥签名，公钥验证。

私钥一般需要通过随机数算法生成，公钥可以根据私钥生成。公钥一般是公开的，他人可获取的；私钥一般是个人持有，他人不能获取。

代表算法包括：RSA、ElGamal、椭圆曲线（Elliptic Curve Crytosystems, ECC）、SM2等系列算法。

## RSA 算法

传统 web2 用的比较多，web3 里的 XML 签名算法使用 RSA 算法。

## 椭圆曲线加密 (ECC)

区块链不直接使用 RSA，而是使用更轻量、更安全的 ECC（Elliptic Curve Cryptography）。

---

### 📐 椭圆曲线数学基础

**椭圆曲线方程：**

```
y² = x³ + ax + b
```

**有限域上的椭圆曲线：**

- 在区块链中，椭圆曲线定义在有限域 GF(p) 上
- 所有运算（加法、乘法）都在模 p 下进行
- 曲线上的点构成一个加法群

**点运算规则：**


| 运算      | 规则                             |
| ------- | ------------------------------ |
| **点加法** | P + Q = R（过P、Q的直线与曲线的第三个交点的镜像） |
| **点倍乘** | kP = P + P + ... + P（k次加法）     |
| **单位元** | 无穷远点 O（相当于加法中的0）               |


---

### 🔐 ECDSA (Elliptic Curve Digital Signature Algorithm)

ECDSA 是区块链中最常用的数字签名算法。

#### 📊 ECDSA 常用曲线


| 曲线名称          | 比特长度 | 安全强度 | 应用场景             |
| ------------- | ---- | ---- | ---------------- |
| **secp256k1** | 256  | 128位 | 比特币、以太坊          |
| **secp256r1** | 256  | 128位 | TLS、Apple Wallet |
| **secp384r1** | 384  | 192位 | 高安全性场景           |
| **secp521r1** | 521  | 256位 | 超高安全性需求          |


#### ⭐ secp256k1 - 区块链的首选

**签名过程：**

设：

曲线阶大质数 n，基点 G
私钥 d，公钥 K=d⋅G
消息 message

1.计算消息哈希：h=SHA256(message)
2.密码学安全随机选取临时随机数 k∈[1,n−1]（每次签名必须换新）
3.计算椭圆曲线点：R=k⋅G
4.取点 R 的横坐标，模 n 得到签名分量：r=x(R)modn若 r=0 则重选 k 重来。
5.计算模 n 下 k 的逆元 k−1，再求第二个签名分量：s=k−1⋅(h+r⋅d)modn若 s=0 则重选 k 重来。
6.最终 ECDSA 签名：(r,s)

**验证过程：**

输入：公钥 K、消息 message、签名 (r,s)

1.先校验：r,s 必须满足 1≤r,s≤n−1，不满足直接非法。
2.计算消息哈希：h=SHA256(message)
3.求 s 在模 n 下的逆元：s−1modn
4.计算两个标量：u1​=h⋅s−1modn,u2​=r⋅s−1modn
5.计算校验点：P=u1​⋅G+u2​⋅K
6.校验规则：取 P 的横坐标，满足x(P)modn=?r相等则签名合法，否则签名无效。

#### ⚠️ ECDSA 的安全风险


| 风险        | 描述            | 防范措施           |
| --------- | ------------- | -------------- |
| **随机数重用** | 重复使用 k 会泄露私钥  | 使用密码学安全的随机数生成器 |
| **侧信道攻击** | 测量运算时间/功耗获取信息 | 常数时间实现         |
| **小私钥攻击** | 私钥熵不足         | 使用高质量随机源       |


---

### 🔑 EDDSA (Edwards-curve Digital Signature Algorithm)

EDDSA 是基于 Edwards 曲线的改进签名算法，提供更好的安全性和性能。

#### ⭐ Ed25519 - 现代标准

**特点：**


| 特性       | 描述                |
| -------- | ----------------- |
| **安全性**  | 抗侧信道攻击，不需要随机数     |
| **性能**   | 签名/验证速度比 ECDSA 快  |
| **密钥大小** | 公钥 32 字节，私钥 32 字节 |
| **签名大小** | 64 字节             |


**Edwards 曲线方程：**

```
-x² + y² = 1 + d·x²·y²
```

**Ed25519 参数：**

- 曲线：Ed25519
- 有限域：GF(2²⁵⁵ - 19)
- d = -121665/121666

**优势：**

1. **确定性签名**：不需要随机数，避免随机数重用风险
2. **抗侧信道攻击**：设计上就是常数时间运算
3. **更快的运算**：签名和验证效率更高

```

```

- 从主私钥派生子私钥
- 支持分层确定性钱包

#### 地址生成


### 📝 面试题：ECDSA 和 EDDSA 算法的区别

**核心区别：**


| 特性        | ECDSA (secp256k1) | EDDSA (Ed25519) |
| --------- | ----------------- | --------------- |
| **曲线类型**  | Weierstrass 曲线    | Edwards 曲线      |
| **安全性**   | 依赖随机数             | 确定性，更安全         |
| **侧信道抗性** | 需特殊实现             | 天生抗侧信道          |
| **签名速度**  | 较慢                | 较快              |
| **验证速度**  | 较慢                | 较快              |
| **密钥大小**  | 公钥 65/33 字节       | 公钥 32 字节        |
| **签名大小**  | 64 字节             | 64 字节           |
| **区块链应用** | 比特币、以太坊           | Solana、Cardano  |


---

**深入分析：**

1. **安全性差异**：
  - ECDSA 需要每次签名生成一个新的随机数 k，如果 k 被重用，私钥就会泄露
  - EDDSA 使用确定性签名算法，不需要随机数，从根本上避免了这个风险
2. **性能差异**：
  - EDDSA 的运算更高效，签名和验证速度都比 ECDSA 快
  - Ed25519 的实现通常是常数时间的，更适合嵌入式设备
3. **曲线选择**：
  - secp256k1 是专门为密码学设计的曲线
  - Ed25519 使用扭曲爱德华曲线，具有更好的数学性质

**总结**：EDDSA 在安全性和性能上都优于 ECDSA，是现代区块链项目的首选。

# 三、数字签名

数字签名是区块链的核心技术之一，用于验证交易的真实性和完整性。

---

### 📝 数字签名基础

**定义：** 一种用于验证消息来源和完整性的密码学技术。

**核心特性：**


| 特性        | 描述              |
| --------- | --------------- |
| **不可伪造性** | 只有私钥持有者才能生成有效签名 |
| **不可否认性** | 签名者无法否认自己的签名    |
| **完整性**   | 消息被篡改后签名将失效     |
| **可验证性**  | 任何人都可以用公钥验证签名   |


**签名流程：**

```
消息 → 哈希函数 → 哈希值 → 私钥签名 → 签名结果
```

**验证流程：**

```
消息 + 签名 + 公钥 → 验证算法 → 有效/无效
```

### 🔐 区块链常用签名算法

#### 1. ECDSA

- **应用**：比特币、以太坊
- **曲线**：secp256k1
- **特点**：经典算法，安全性高，但需要随机数

#### 2. EDDSA

- **应用**：Solana、Cardano、Monero
- **曲线**：Ed25519
- **特点**：确定性签名，抗侧信道攻击，速度更快

#### 3. BLS 签名

- **应用**：以太坊 2.0、Polkadot、Filecoin
- **特点**：支持签名聚合，适合分片和共识

#### 4. Schnorr 签名

- **应用**：比特币 Taproot、以太坊（未来）
- **特点**：支持签名聚合，更高效

### 🔑 多重签名 (Multi-Signature)

#### 🎯 M-of-N 多签机制

**原理：** 需要 M 个私钥中的 N 个来共同签名才能完成交易。

**示例场景：**

- **2-of-3 多签**：3个管理员中需要2个同意才能转账
- **3-of-5 多签**：5个董事会成员中需要3个授权

**应用场景：**


| 场景         | 多签配置   | 用途     |
| ---------- | ------ | ------ |
| **企业钱包**   | 3-of-5 | 防止单点故障 |
| **DAO 金库** | 多重签名   | 社区治理   |
| **交易所冷钱包** | 4-of-7 | 高安全存储  |


**技术实现：**

**方案一：智能合约多签**

```solidity
// Gnosis Safe 多签合约
contract MultiSigWallet {
    address[] public owners;
    uint public required;

    function executeTransaction(address to, uint value, bytes data) public {
        // 验证签名数量 >= required
        require(isConfirmed(txId), "Not enough signatures");
        // 执行交易
        (bool success, ) = to.call{value: value}(data);
        require(success, "Transaction failed");
    }
}
```

**方案二：OP_CHECKMULTISIG (比特币)**

```
OP_2                    // 需要 2 个签名
<公钥1> <公钥2> <公钥3>  // 3 个公钥
OP_3                    // 总共 3 个公钥
OP_CHECKMULTISIG        // 验证多签
```

**多签优缺点：**


| 优点     | 缺点      |
| ------ | ------- |
| 提高安全性  | 操作复杂度增加 |
| 防止单点故障 | 需要多方协调  |
| 去中心化控制 | 延迟可能增加  |


---

### 📊 多签 vs 单签对比


| 特性       | 单签      | 多签       |
| -------- | ------- | -------- |
| **密钥管理** | 单私钥     | 多私钥分散管理  |
| **安全性**  | 私钥泄露即被盗 | 需要多个私钥泄露 |
| **可用性**  | 单点故障    | 容错性高     |
| **效率**   | 快速      | 需要多方签名   |
| **适用场景** | 个人钱包    | 企业/组织钱包  |


---

### ⚠️ 多签安全注意事项

1. **私钥分发**：私钥应物理分散存储
2. **门限设置**：根据风险评估设置合理的 M/N
3. **密钥轮换**：定期更换私钥
4. **审计日志**：记录所有签名操作
5. **应急方案**：制定私钥丢失的应对措施

# 四、TSS 分布式门限签 (Threshold Signature Scheme)

TSS 是一种更先进的密钥管理方案，将私钥分散存储在多个节点。

---

### 🎯 TSS 核心概念

**原理：** 私钥不完整存在任何一个地方，而是被分割成多个份额。

**Shamir 秘密共享：**

- 将私钥 k 拆分成 n 个份额
- 任意 t 个份额可以恢复出完整私钥
- 少于 t 个份额无法恢复私钥

**门限签名流程：**

```
1. 密钥生成阶段：各节点协同生成密钥份额
2. 签名阶段：各节点用份额独立签名
3. 签名聚合：将部分签名聚合成完整签名
```

---

### 🔐 TSS vs 多签对比


| 特性         | 多签       | TSS       |
| ---------- | -------- | --------- |
| **私钥形式**   | 多个独立私钥   | 一个私钥的多个份额 |
| **签名大小**   | N 个签名    | 1 个签名     |
| **验证成本**   | 验证 N 个签名 | 验证 1 个签名  |
| **交易大小**   | 较大       | 正常大小      |
| **Gas 费用** | 高        | 正常        |
| **去中心化程度** | 较高       | 更高        |


---

### 📊 TSS 类型


| 类型                | 描述       | 应用    |
| ----------------- | -------- | ----- |
| **(t, n) 门限**     | t 个份额可签名 | 通用场景  |
| **分布式密钥生成 (DKG)** | 无中心化密钥生成 | 高安全场景 |
| **可验证秘密共享 (VSS)** | 可验证份额正确性 | 不信任场景 |


---

### 🌐 TSS 应用场景


| 场景         | 优势      |
| ---------- | ------- |
| **托管钱包**   | 无需信任托管方 |
| **交易所冷存储** | 防止单点故障  |
| **DAO 治理** | 去中心化决策  |
| **跨链桥**    | 安全的资产转移 |


---

### 💡 TSS 实现示例

**简化的 Shamir 秘密共享：**

```python
from shamir import ShamirSecretSharing

# 初始化：将私钥分成 5 份，需要 3 份恢复
sss = ShamirSecretSharing(threshold=3, num_shares=5)

# 拆分私钥
private_key = b"my_secret_key"
shares = sss.split(private_key)

# 用 3 个份额恢复私钥
recovered_key = sss.recover(shares[:3])
assert recovered_key == private_key
```

# 五、BLS 算法 (Boneh-Lynn-Shacham)

一种基于双线性对的数字签名算法。

BLS 是一种高效的签名方案，支持签名聚合。实现聚合签名，把成千上万节点的签名压缩成 1 个，大幅减少共识数据量，提升链上性能。基于 BN254/BLS12-381 曲线

---

### 🎯 BLS 核心特性

**签名聚合：** 多个签名可以聚合成一个签名。

**优势：**


| 特性       | 描述              |
| -------- | --------------- |
| **签名聚合** | n 个签名 → 1 个聚合签名 |
| **验证效率** | 一次验证多个签名        |
| **节省空间** | 聚合签名大小固定        |
| **适合分片** | 以太坊 2.0 使用      |


**应用场景：**

- **以太坊 2.0 共识**：验证委员会成员签名
- **PoS 质押**：批量验证验证者签名
- **跨链桥**：验证多条链的状态

# 六、MPC 算法 (Multi-Party Computation)

MPC 允许多方在不泄露各自输入的情况下共同计算。

---

### 🎯 MPC 核心概念

**隐私保护计算：**

- 各方持有秘密输入
- 共同计算函数
- 只公布计算结果，不泄露输入

**应用场景：**


| 场景         | 用途     |
| ---------- | ------ |
| **隐私交易**   | 隐藏交易金额 |
| **联合数据分析** | 保护数据隐私 |
| **安全投票**   | 匿名投票   |


---

### 🔐 MPC vs TSS vs 多签


| 特性       | 多签   | TSS | MPC  |
| -------- | ---- | --- | ---- |
| **密钥形式** | 多个私钥 | 份额  | 秘密输入 |
| **计算类型** | 签名   | 签名  | 任意计算 |
| **隐私保护** | 低    | 中   | 高    |
| **复杂度**  | 低    | 中   | 高    |

# 七、ZK 零知识证明 (Zero-Knowledge Proof)

零知识证明允许证明者向验证者证明某个陈述为真，而不泄露任何其他信息。

---

### 🎯 ZK 核心概念

**定义：** 一种密码学协议，满足三个性质：

1. **完备性**：真陈述可以被证明
2. **可靠性**：假陈述无法被证明
3. **零知识性**：验证者除了知道陈述为真外，得不到任何其他信息

**应用场景：**


| 场景       | 用途          |
| -------- | ----------- |
| **隐私交易** | Zcash、Aztec |
| **扩容方案** | zkRollup    |
| **身份验证** | 匿名身份证明      |


---

### 🔐 常见 ZK 证明系统


| 系统               | 特点      | 应用           |
| ---------------- | ------- | ------------ |
| **zk-SNARK**     | 简洁、快速验证 | Zcash、zkSync |
| **zk-STARK**     | 无需可信设置  | StarkNet     |
| **Bulletproofs** | 无需可信设置  | Monero       |


---

### 📊 ZK 证明流程

**通用流程：**

```
1. 定义电路：描述要证明的陈述
2. 生成证明：证明者生成 ZK 证明
3. 验证证明：验证者验证证明有效性
```

**zk-SNARK 流程：**

```
1. 可信设置：生成公共参数
2. 证明生成：prover(x, w) → π
3. 证明验证：verifier(x, π) → true/false
```
